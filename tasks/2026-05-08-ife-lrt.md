# Improved Fuel Efficiency (IFE) LRT Implementation

**Date:** 2026-05-08
**Goal:** Unlock the IFE LRT for race selection and wire its three effects: ×0.85 fuel consumption during fleet movement, +1 starting Propulsion level, and `lrt_required` / `lrt_forbidden` tagging on Fuel Mizer and Galaxy Scoop so they are buildable only by IFE races (Galaxy Scoop additionally blocked by NRSE).
**Relevant PRDs:** [22 — Race Design](docs/prd/22-race-design.md) §"Lesser Racial Traits", §"Schema Changes" (catalogue restrictions); [10 — Fleet Movement](docs/prd/10-fleet-movement.md) (fuel formula); [20 — Components Catalogue](docs/prd/20-design-components-catalogue.md)

---

## Background

The HE PRT task ([2026-05-04-he-prt.md](tasks/2026-05-04-he-prt.md)) added the `prt_required` / `prt_forbidden` / `lrt_required` / `lrt_forbidden` fields to `ComponentCatalogueEntry` and wired `_check_race_restrictions` into `build_design`. So the schema and enforcement are already in place — IFE just needs to populate the LRT fields on Fuel Mizer / Galaxy Scoop and stop the validator rejecting `race.lrts` outright.

The IFE effects from the PRD that this task implements:

1. **Fuel consumption ×0.85** — applied per-ship inside `_fuel_for_leg` in [movement.py](backend/openstars/engine/resolve_steps/movement.py). Owner race is looked up via `ctx.race_by_username[fleet.owner]`. Integer-only: `ship_fuel = ship_fuel * 17 // 20`.
2. **+1 starting Propulsion level** — applied in `_apply_starting_tech_levels` in [turn_zero.py](backend/openstars/engine/resolve_steps/turn_zero.py) as `levels["propulsion"] = max(current, 1)` when `LRT.IMPROVED_FUEL_EFFICIENCY in race.lrts`. Does **not** stack with future CE +1 (each is `max(current, 1)`); does **not** override JOAT's `max(current, 3)` base.
3. **Catalogue restrictions** — `lrt_required: [IFE]` on Fuel Mizer; `lrt_required: [IFE]` + `lrt_forbidden: [NRSE]` on Galaxy Scoop. The NRSE forbid is forward-looking — NRSE isn't yet selectable, but tagging the catalogue now means the next LRT task doesn't have to revisit Galaxy Scoop.

Out of scope for this task:

- **NRSE LRT itself** — only the Galaxy Scoop `lrt_forbidden` tag lands here. NRSE selectability and its other ramscoop restrictions are a separate task.
- **Other LRTs (TT, ARM, ISB, GR, UR, MA, CE, OBRM, NAS, LSP, BET, RS)** — each remains gated by the validator.
- **IFE intel detection** — the PRD notes IFE is detectable from observed fuel consumption. Trait-detection mechanics are deferred per PRD 22 §"Out of scope".
- **Predefined races that include IFE** (Humanoid is already shipped without IFE; Rabbitoid / Silicanoid / Antethereal include IFE but require their PRTs which aren't selectable). They land with their PRTs.

## Step 2 — Fuel consumption ×0.85

The fuel-per-leg calculation lives in `_fuel_for_leg` in [movement.py](backend/openstars/engine/resolve_steps/movement.py). The owner race is reachable via `ctx.race_by_username` but `_fuel_for_leg` is currently context-free, so we plumb the multiplier in as an integer keyword argument and resolve it once per `move_fleet` call.

The PRD wording is "fuel consumption ×0.85". We apply this **per-ship** after the existing rounded ship-fuel calculation, using integer math so the result stays deterministic:

```
ship_fuel = ((ship_mass * design.fuel_usage[warp - 1] * distance_light_years // 200) + 9) // 10
ship_fuel = ship_fuel * fuel_multiplier_x100 // 100   # 85 for IFE, 100 otherwise
```

`* 17 // 20` would also work; we use `* fuel_multiplier_x100 // 100` so future LRT/PRT multipliers (none in scope here) slot into the same dispatch.

Edit [movement.py](backend/openstars/engine/resolve_steps/movement.py).

- [x] Add `from openstars.engine.race.models import LRT, Race` near the existing imports.
- [x] Add a module helper:
  ```python
  def _fuel_multiplier_x100(race: Race | None) -> int:
      if race is not None and LRT.IMPROVED_FUEL_EFFICIENCY in race.lrts:
          return 85
      return 100
  ```
- [x] Extend `_fuel_for_leg` signature with `*, fuel_multiplier_x100: int = 100`. Inside the per-ship loop, after `ship_fuel = ((... + 9) // 10)`, apply `ship_fuel = ship_fuel * fuel_multiplier_x100 // 100`. Default of 100 keeps every existing call site unchanged.
- [x] Extend `_effective_warp` signature with the same `*, fuel_multiplier_x100: int = 100` keyword and forward it into both `_fuel_for_leg` calls inside the function body. The auto-warp-down logic must use the IFE-discounted fuel cost or it would skip warp tiers the fleet can actually afford.
- [x] In `move_fleet`, near the top (before the `while waypoints` loop) compute `fuel_multiplier_x100 = _fuel_multiplier_x100(ctx.race_by_username.get(fleet.owner))` once. Pass it as a keyword argument to every `_effective_warp` and `_fuel_for_leg` call inside this function (there are two of each — the arrived-at-waypoint branch and the moved-partial-distance branch).
- [x] Unit tests in [test_movement.py](backend/tests/engine/test_movement.py) (or wherever movement tests already live — check `backend/tests/engine/` for the existing file; if none exists yet, create `test_fuel.py` under `backend/tests/engine/`):
  - `_fuel_multiplier_x100(None)` returns 100.
  - `_fuel_multiplier_x100(race_with_no_lrts)` returns 100.
  - `_fuel_multiplier_x100(race_with_IFE)` returns 85.
  - `_fuel_multiplier_x100(race_with_TT)` returns 100 (any non-IFE LRT is unchanged).
  - `_fuel_for_leg(fleet, designs, warp=6, distance=10, fuel_multiplier_x100=100)` matches the pre-change value for an existing fleet/design fixture (regression).
  - `_fuel_for_leg(... fuel_multiplier_x100=85)` returns floor(non_ife_value * 85 / 100) for the same fixture (allow ±1 per ship from per-ship floor; assert against the explicitly recomputed expected value, not a hand-typed integer).
  - End-to-end via `move_fleet`: a fleet owned by an IFE race travelling a fixed distance has its `fleet.fuel` reduced by exactly 85% of the equivalent non-IFE consumption (set up two parallel `TurnContext`s — one with IFE, one without — over the same fleet/design and assert).
  - Auto-warp-down: a fleet with limited fuel that would have been forced to warp 4 without IFE can sustain warp 5 with IFE (constructed so the warp-5 cost falls just above the budget at 100% but just below at 85%).

## Step 3 — Starting Propulsion +1

Edit `_apply_starting_tech_levels` in [turn_zero.py](backend/openstars/engine/resolve_steps/turn_zero.py). The function already applies JOAT's `max(current, 3)` base and the `start_at_tech_3` accelerator; IFE slots in as a third pass.

Order matters: JOAT base first (sets all to ≥3), then accelerator (lifts expensive fields to 3 or 4), then IFE (lifts propulsion to ≥1 — a no-op for JOAT but meaningful for HE and any future PRT with 0 starting levels).

- [x] After the existing accelerator block, add:
  ```python

      new_levels["propulsion"] = max(new_levels["propulsion"], 1)
  ```
  Add `LRT` to the imports from `openstars.engine.race.models` (currently imports `PRT`).
- [x] Unit tests in [test_turn_zero_resolution.py](backend/tests/engine/race/test_turn_zero_resolution.py):
  - HE race with `lrts={IFE}` resolves to `propulsion == 1`, all other fields `0`.
  - HE race with no LRTs resolves to `propulsion == 0` (regression — confirms the change is gated on the LRT flag).

  - JOAT race with `lrts={IFE}`, `start_at_tech_3=True`, `propulsion` profile `expensive` resolves to `propulsion == 4` (accelerator wins).
